## 3. 数据库设计

### 3.1 用户服务数据库 (user_db)

#### 用户表 (users)

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    display_name VARCHAR(100),
    avatar_url VARCHAR(500),
    status TINYINT DEFAULT 1 COMMENT '0:禁用 1:正常',
    role VARCHAR(20) DEFAULT 'USER' COMMENT 'USER/ADMIN',
    storage_quota BIGINT DEFAULT 5368709120 COMMENT '默认5GB',
    storage_used BIGINT DEFAULT 0,
    last_login_at DATETIME,
    last_login_ip VARCHAR(50),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at DATETIME,
    INDEX idx_username (username),
    INDEX idx_email (email),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 用户组表 (user_groups)

```sql
CREATE TABLE user_groups (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    group_name VARCHAR(100) NOT NULL,
    description VARCHAR(500),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_group_name (group_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 用户组成员表 (user_group_members)

```sql
CREATE TABLE user_group_members (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    group_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_group_user (group_id, user_id),
    INDEX idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.2 文档服务数据库 (document_db)

#### 文档表 (documents)

```sql
CREATE TABLE documents (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    uuid VARCHAR(36) NOT NULL UNIQUE,
    filename VARCHAR(255) NOT NULL,
    file_size BIGINT NOT NULL,
    file_type VARCHAR(50) NOT NULL,
    mime_type VARCHAR(100),
    storage_path VARCHAR(500) NOT NULL,
    storage_bucket VARCHAR(100),
    file_hash VARCHAR(64) COMMENT 'SHA-256 for deduplication',
    folder_id BIGINT,
    owner_id BIGINT NOT NULL,

## 6. 关键技术方案

### 6.1 文件上传方案

**分块上传流程**：

```
1. 初始化分块上传
   POST /api/storage/multipart/init
   → 返回 uploadId

2. 分块上传（并行）
   POST /api/storage/multipart/{uploadId}
   → 每块 5MB，支持并行

3. 完成分块上传
   POST /api/storage/multipart/{uploadId}/complete
   → 合并文件，生成 SHA-256 校验

4. 取消上传（如失败）
   DELETE /api/storage/multipart/{uploadId}
```

**断点续传**：
- 前端记录已上传分块列表
- 刷新页面后从已上传分块继续
- 后端记录分块状态，支持查询

### 6.2 在线编辑方案

**技术选型**：
- 后端：OnlyOffice Document Server 或 Microsoft Office Online Server
- 前端：@onlyoffice/document-editor-react

**协同编辑**：
- WebSocket 连接 Document Server
- 支持多人同时编辑
- 实时显示用户光标和选区

### 6.3 CAD 预览方案

**技术选型**：
- 前端：Autodesk Forge Viewer 或 Three.js + DWGLoader
- 后端：ODA (Open Design Alliance) SDK 或 Teigha

**流程**：
```
1. 上传 CAD 文件
2. 后端异步转换（如 DWG → SVG/JSON）
3. 生成缩略图
4. 前端加载预览
```

### 6.4 全文检索方案

**技术选型**：Elasticsearch 8.x

**索引策略**：
- 文档内容通过 Apache POI 提取
- 中文分词：IK Analyzer
- 支持 PDF/Word/Excel/TXT 内容索引

**搜索优化**：
- 搜索结果按相关度 + 时间排序
- 启用 search template 缓存
- 按条件 hash 缓存搜索结果

### 6.5 缓存策略

**Redis 缓存设计**：

| 缓存 Key | 用途 | TTL |
|----------|------|-----|
| user:{userId} | 用户信息 | 1h |
| doc:{docId} | 文档元数据 | 30min |
| doc:{docId}:permissions | 文档权限 | 1h |
| search:{hash} | 搜索结果 | 5min |
| presigned:{fileId} | 预签名URL | 15min |
| category:tree | 分类树 | 1h |
| quota:{userId} | 用户配额 | 1h |

**缓存更新策略**：
- 写入时删除相关缓存（Cache Aside）
- 支持手动刷新管理接口
- 分布式环境下通过 Redis Pub/Sub 同步

### 6.6 消息通知方案

**事件驱动架构**：
- 文档操作发布事件到内部消息队列
- 各服务订阅相关事件
- 异步处理（避免阻塞主流程）

**通知发送**：
- 站内通知：存储到数据库，WebSocket 推送
- 邮件通知：通过队列发送，支持重试

```

**单机模式特性**：
- 所有微服务运行在单一 JVM 进程中
- 使用嵌入式数据库（H2/MySQL 单实例多库）
- 服务间通过内部调用（非 HTTP）
- Nacos/Sentinel 作为可选依赖（可禁用）
- 最低硬件要求：4核CPU / 8GB内存

#### 7.2.3 Maven Profile 配置

在 `pom.xml` 中配置打包 profile：

```xml
<profiles>
    <!-- 单机部署模式 -->
    <profile>
        <id>standalone</id>
        <activation>
            <activeByDefault>true</activeByDefault>
        </activation>
        <properties>
            <profile.name>standalone</profile.name>
            <spring.profiles.active>standalone</spring.profiles.active>
            <!-- 单机模式使用 H2 嵌入式数据库 -->
            <jdbc.driver>org.h2.Driver</jdbc.driver>
            <!-- 禁用微服务特性 -->
            <feign.enabled>false</feign.enabled>
            <ribbon.enabled>false</ribbon.enabled>
        </properties>
    </profile>

    <!-- 分布式部署模式 -->
    <profile>
        <id>distributed</id>
        <properties>
            <profile.name>distributed</profile.name>
            <spring.profiles.active>distributed</spring.profiles.active>
            <jdbc.driver>com.mysql.cj.jdbc.Driver</jdbc.driver>
            <feign.enabled>true</feign.enabled>
            <ribbon.enabled>true</ribbon.enabled>
        </properties>
    </profile>

    <!-- 开发环境 -->
    <profile>
        <id>dev</id>
        <properties>
            <spring.profiles.active>dev</spring.profiles.active>
        </properties>
    </profile>

    <!-- 生产环境 -->
    <profile>
        <id>prod</id>
        <properties>
            <spring.profiles.active>prod</spring.profiles.active>
        </properties>
    </profile>
</profiles>
```

#### 7.2.6 部署模式对比

| 特性 | 单机模式 | 分布式模式 |
|------|----------|------------|
| 部署复杂度 | 低（单 jar） | 高（多服务） |
| 硬件要求 | 4核8GB | 16核32GB+ |
| 并发能力 | 50-100用户 | 500+用户 |
| 水平扩展 | 不支持 | 支持 |
| 服务隔离 | 无 | 完全隔离 |
| 故障影响 | 单点故障 | 服务隔离 |
| 适用场景 | 开发/测试/小团队 | 中大型企业 |
| 升级方式 | 全量升级 | 滚动升级 |
| 监控复杂度 | 简单 | 复杂 |
| 存储需求 | 单节点 | 集群 |

## 8. 安全设计

### 8.1 认证授权

**JWT Token**：
- Access Token：15分钟有效期
- Refresh Token：7天有效期，存储在 HTTP Only Cookie

**权限模型**：RBAC + 资源权限
- 角色：超级管理员、普通用户、审计员
- 资源权限：READ/WRITE/DELETE/MANAGE

### 8.2 安全措施

- 密码 bcrypt 加密（强度因子 12）
- API 限流（每 IP 100次/分钟）
- SQL 注入防护（参数化查询）
- XSS 防护（输入过滤 + 输出编码）
- CSRF Token 验证
- 敏感操作日志记录

- 组件文件：PascalCase（如 UserList.tsx）
- 工具函数：camelCase
- CSS 类：kebab-case
- API 接口：camelCase
